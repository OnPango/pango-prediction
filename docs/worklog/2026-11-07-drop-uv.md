# Drop uv: one pip setup for Windows and the cloud

**Date:** 2026-11-07 · **Branch:** `feature/drop-uv` → `dev`

## Goal

Remove `uv` from the project's instructions. The owner could not install it on their machine, so the documented setup did not work for them.

There was already evidence against `uv`:

- `docs/domain-rules.md` recorded the `uv` commands in the README as stale (discrepancy 3);
- `docker/Dockerfile.api` installs with `pip`.

The `uv` lines in `AGENTS.md` and the PR template came in with `feature/dev-workflow` (OnPango/pango-prediction#3). That was a regression, and this branch corrects it.

## Decisions

- **The install is a single `python -c` line that reads `pyproject.toml`.**
  - It keeps `pyproject.toml` as the only list of dependencies, as the Dockerfile does.
  - It works in both PowerShell and bash.
  - It needs neither a build backend nor `pip` 25.1. `pip install --group` would need that version, and the cloud's `pip` is 24.0.
  - Listing the packages by hand in the docs was rejected, because that list would drift from `pyproject.toml`.
- **The Dockerfile and `docs/ROUTE_B_STATUS.md` are not touched.** They mention `uv` only inside the open lock-file decision. With `uv` dropped, that decision narrows to `pip-tools` or no lock.
- **The `2026-11-07-dev-workflow` worklog entry keeps its `uv run` check names.** Entries are not rewritten after merge; this entry records the correction.

## Open questions
